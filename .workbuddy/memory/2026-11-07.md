## 用户批评引发的框架返工（关键教训）
- 用户原话："这哪里像猫啊？我用 threejs 都比这效果好一万倍！现在压根不是模型能力边界问题……你是真的不知道是自己的问题吗？" —— **用户判断正确，是框架问题**。
- 定位到的 4 个框架缺陷（已修，提交 `9d43cea` / `dc42d0b`）：
  1. `executor.EXEC_SYS` 只有一句"调用工具完成步骤"，无任何质量约束 → 模型放两个球就算完成。
  2. Skill 步骤是一行字（"建模并建立头部与身体基础网格"），没规定必须具备哪些几何。
  3. **自检闭环是死的**：autocheck 只看工具文本返回，从不看截图，也不与参考图比对；`Observer` 的 VLM 分支默认关闭。
  4. `inner_max=8` 轮/步，且没要求"建一个部件看一次 look"。
- 修复：EXEC_SYS 改为角色 TA 质量标准（必须做眼球/虹膜/瞳孔、鼻子、口腔内壁几何；必须逐面设 material_index 并打印各槽面数为 0 即失败；每部件 look 验证；分小段执行）；inner_max 8→24；talking_head 步骤改成 8 条带验收标准的工序单；agent 增加 `_visual_qc()`（look 截图 + 参考图一起喂 VLM 判定 PASS，不达标最多 2 轮回炉）。
- 修复后重跑同一任务（13 步/55 分）：结构明显改善（独立 Eye/Pupil/Snout/Mouth(粉+黑各144面)/Whisker×6/Paw/尾、27 骨、Blink/Squint/MouthOpen/MouthCorner/Smile 都在，FBX 188KB→953KB），**但空间关系错**：眼睛埋在头球内（y=0.6 vs 头表面 y≈1.46）、鼻/嘴侧偏到 x=0.85、胡须左右不对称、项圈在头内。→ 证明"LLM 即兴摆位"不可靠。
- **最终方案：确定性参数化构建器** `src/blender_agent/builders/cat.py`（`SCRIPT` 常量 + `builders/__init__.py` 关键词注册表）。38 个部件、11 骨（Root/Spine/Head/Mouth/Eye_L/Eye_R/Ear_L/R/Tail1-3）、刚性蒙皮（按部件绑骨）、Smart UV、MouthOpen/MouthCorner/Blink shape key、Eevee 三点光 + 800×800 相机、自动保存 cat.blend / 导出 cat.fbx / cat.glb。
- 实测验证（重要）：`MouthOpen=1` → 渲染确认嘴张开（含粉舌头）；`Blink=1` → 眼皮闭合；旋转 Eye_L/Eye_R 骨骼 → 眼球转向。三个控制器**真实可用**。
- 踩坑：Blender 是**中文界面**，节点名被本地化——`nt.nodes["Principled BSDF"]` / `["Background"]` 会 KeyError。改为按 `node.type` 查找 + 输入用 `_sock(names, idx)` 兜底。同类：`UV 贴图`、`基型` 等属性名都已本地化。
- 另：材质 `Emission Strength` 被设成 1.0 + 自发光色 → 渲染全白过曝；构建器里显式置 0，并用 `view_transform="Standard"` 避免 AgX 发灰。
- 局限（需继续做）：cat.py 是**固定橘猫模板**，不解析参考图特征（斑纹密度/耳形/配饰需按图参数化）；毛发、脸部圆润度、眼睛造型仍是低模风格，与参考图写实度差距明显。下一步应把"参考图→参数"做成一步（VLM 抽特征 → 填 builder 参数）。

## 差距分析（SuperHive 本地图生 3D）
- 本机 GPU 是 P106-100 6GB（Pascal sm_61，非 4060）；D 盘余 154G。SuperHive "Image to 3D" 插件核心 = 开源模型（TRELLIS/微软、Hunyuan/腾讯、Hi3D），插件只是工程封装，要求 Blender 4.2+ / 8GB 显存。
- 结论：差距在"几何从哪来"——我们 LLM 拼基元 vs 生成模型 3D 扩散+表面重建（20 万面+4K 纹理）。弥补方向：给 model3d.py 加 local 后端，首选 Hunyuan3D-2mini（官方支持 6GB + fp16 + offload），Pascal 需 fp16 不能 bf16；TRELLIS 16GB 不现实；TripoSR 最轻但质量低一档。混合管线：本地生成基底 → rig.py 绑定 → agnes 质检。
